# Stage 0–10 工作流

全流程以 `state/decision_log.json` 为单一状态源，以实际文件、哈希和命令输出为证据。每道子问题最多保留两个真正独立的模型族；误差分析、消融、灵敏度和不同边界条件通常不另算模型族。

| Stage | 任务 | 主要产物 | 退出条件 |
|---|---|---|---|
| 0 | 启动、资料盘点、当届规则核验、环境预检、时间分配 | 规则台账、输入清单、环境预检记录、项目状态 | 赛题/规则版本和提交边界明确；编译链、Python 依赖、绘图中文字体、文献检索连通性可用 |
| 1 | 多题预扫与选题 | 选题矩阵、风险表、题号决策 | 用户确认题目或已有题号固定 |
| 2 | 题意分解与数据边界 | 子问题合同、采分点矩阵、题目交付物清单、数据台账、实验单位图、外部数据分类 | 每个目标、输入、输出、约束、指标明确；矩阵与交付物清单无空项 |
| 3 | 候选模型与反事实比较 | 候选模型表、强基线、拒绝理由、验证设计 | 模型可实现且复杂度有理由 |
| 4 | 基础定义 | 假设、符号、单位、公式、参数辨识方案 | 符号唯一、量纲和约束闭合；M1 PASS |
| 5 | 递归求解 Q1…Qn | 权威代码、逐问结果、过程日志、最小复现 | P1 PASS 后全量；各问结果可复现 |
| 6 | 全局验证 | 分组/嵌套验证、消融、压力测试、误差与不确定性 | 无未解释泄漏或验证偏乐观 |
| 7 | 综合评价与建议 | 优缺点、适用域、失败区间、工程/管理建议 | P2 PASS，模型—结论边界明确 |
| 8 | 证据大纲和论文写作 | Claim–Evidence Map、章节文件、参考文献 | W1 PASS 后写长文，所有数字有来源 |
| 9 | 排版、图表、自然表达与渲染 | 最终正文、正式图表、渲染预览 | 确定性文档校验与 W2 PASS |
| 10 | 支撑材料、合规、15 专家闭环 | 提交包、评分轮次、最终清单 | 平均分≥92且无致命项 |

## 固定独立门禁

- `M1`：题意覆盖、假设、公式、单位、模型数量、可实现性、验证方案、文献来源。
- `P1`：从项目根目录执行最小纵向切片，核对输入→预处理→求解→结果、退出码和约束。
- `P2`：冻结代码、结果和图表后独立复现，核对输入哈希、种子、依赖、数值和图表语义。
- `W1`：逐问核对“结论—公式—结果表—图—代码输出—文献”落点，并逐项核对采分点矩阵与题目交付物清单，无空项、无漏交。
- `W2`：冻结文档后核对规则、数值、单位、引用、实际渲染和多格式一致性。

任何 P0（题意、正确性、官方硬约束）或 P1（复现、一致性、关键质量）问题均返回 FAIL。质检者只给证据、页码、路径、命令和返工入口，不替作者直接改稿。

## 采分点矩阵与题目交付物清单

Stage 2 从题面逐句提取两份合同，W1 与专家 E01/E02 按此逐项核对；漏掉一项都是评委可直接扣分的硬伤：

- **采分点矩阵**：`任务/小问 → 论文章节 → 公式/表/图 → 结论落点`，一问一行。题面每一个评分动作（“给出…”“比较…”“写出…”“评估…”“预测…”）都必须有独立落点，禁止把整问合并写成“见第 x 章”。
- **题目交付物清单**：题目要求提交的每一项非正文产物——memo/letter/邮件、指定格式的结果表、指定文件名与命名规则、摘要页/篇幅限制、支撑材料的特殊要求，逐项写明格式、目标读者、限制和在提交包中的落点（论文、附录还是支撑材料）。未列入清单的额外产物不进入提交包。

## 每个子问题的最小闭环

对 Q1…Qn 依次保存：

`问题合同 → 数据切片 → 假设 → 模型 → 算法 → 参数 → 结果 → 验证 → 解释 → 失败条件`

若后续子问使用前一问输出，必须保存接口、单位、误差传递和版本哈希。禁止在后续子问重新手填一个“更好看”的上游结果。

时间不足可缩减候选模型、绘图数量或非关键扩展，但不能跳过官方合规、数据泄漏、真实运行、主张—证据和最终评分门槛。范围变化由用户确认并写入状态。

## 已有论文接管

没有状态文件但已有论文/代码时，不假定任何前置阶段已通过。只读导入并记录哈希，抽取论文主张和数字，逐一定位到代码、结果、数据或文献；从最早出现证据缺口的阶段恢复。旧稿只作输入，不直接成为权威终稿。

## 48 小时时间盒

按剩余时间比例设置节点：前 10% 完成规则与题意冻结，前 25% 完成数据边界和 M1，前 55% 完成 P1 与主模型，前 70% 完成全量验证和 P2，前 85% 完成 W1 与正文，前 93% 完成 W2、Checkpoint V1 和提交包，至少保留最后 7% 做 panel、返工与上传复核。V1 是"完整、可打开、满足已核验硬约束"的物理可提交保底，先于 92 分放行产生；协议见 [delivery-deadline.md](delivery-deadline.md)。节点可随题目调整，但上传缓冲、V1 保底和硬门禁不得被可选扩展挤占。
